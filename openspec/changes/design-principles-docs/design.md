## Context

Docusaurus is already installed and running. The `docs` preset is disabled (`docs: false`). The site has a blog and static pages. Re-enabling docs is a config change — no new dependency needed.

## Goals / Non-Goals

**Goals:**
- Enable the docs plugin with a `design-principles` category
- Add a navbar link pointing to the docs section
- Provide one mock doc so the structure is browsable immediately

**Non-Goals:**
- Actual design principle content (placeholder only)
- Custom sidebar configuration beyond Docusaurus autogeneration
- Docs versioning or i18n

## Decisions

**Use Docusaurus autogenerated sidebar**
Rather than maintaining a manual `sidebars.ts`, rely on Docusaurus's `autogenerated` sidebar type. The `docs/design-principles/` directory structure drives the sidebar automatically. No `sidebars.ts` changes needed.

**Place docs under `docs/design-principles/`**
Using a subdirectory (rather than flat `docs/`) keeps the structure extensible — other doc categories can be added alongside `design-principles/` later.

**Mock doc as `mock-design-principle.md`**
A single placeholder file validates the full pipeline (config → sidebar → rendered page) without committing to real content.

## Risks / Trade-offs

- **`onBrokenLinks: 'throw'`** → If any internal link in the mock doc is broken, the build fails. Keep the mock doc self-contained with no internal links.
